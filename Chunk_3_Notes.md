# Project 3 — Chunk 3: The Autonomous ReAct Agent Loop

## 1. What is the ReAct Loop? (Reason + Act)
In Chunk 2, our graph was a one-way street: `START -> chatbot -> END`.
In Chunk 3, we turned it into an **autonomous decision-making cycle**:

```
                  ┌──────────────────────┐
                  │        START         │
                  └──────────┬───────────┘
                             │
                             ▼
                    ┌─────────────────┐
               ┌───►│  chatbot node   │
               │    └────────┬────────┘
               │             │
               │      (Traffic Cop: tools_condition)
               │      Did Gemini request tools?
               │             │
               │       ┌─────┴─────┐
    (Result)   │       ▼           ▼
               │     [ YES ]     [ NO ] ──► END (Final Answer)
               │       │
               │       ▼
               │   ┌───────────┐
               └───┤ tool_node │
                   └───────────┘
```

---

## 2. The Core Building Blocks

### A. `ToolNode` (Automated Tool Station)
- Instead of writing manual loops to match names, run `.invoke()`, and construct `ToolMessage`s, `ToolNode` does all of that automatically:
```python
from langgraph.prebuilt import ToolNode

builder.add_node("tools", ToolNode(tools))
```

### B. `tools_condition` (The Traffic Cop)
- A **Conditional Edge** creates a fork in the road.
- `tools_condition` inspects the last message generated by the chatbot:
  - If it contains `tool_calls` $\rightarrow$ routes to `"tools"`.
  - If it does NOT contain `tool_calls` $\rightarrow$ routes to `END`.
```python
from langgraph.prebuilt import tools_condition

builder.add_conditional_edges("chatbot", tools_condition)
```

### C. The Cyclic Edge (The Loop)
- Once the tools execute, the road leads **straight back to `chatbot`**:
```python
builder.add_edge("tools", "chatbot")
```
- This allows the model to read the tool answers and either:
  1. Synthesize the final answer, OR
  2. Call another tool if it needs more information!

## 3. The 5-Step Trajectory
When we ran: *"What is the weather in London right now, and what is 24 multiplied by 7?"*, the agent went through 5 distinct steps:

1. **Step 1 (`HumanMessage`):** The user prompt enters `START`.
2. **Step 2 (`AIMessage`):** Gemini decides it needs tools and requests `get_current_weather` & `multiply_numbers`.
3. **Step 3 (`ToolMessage`):** `ToolNode` executes `get_current_weather("London")` $\rightarrow$ returns `"12°C, Light drizzle"`.
4. **Step 4 (`ToolMessage`):** `ToolNode` executes `multiply_numbers(24, 7)` $\rightarrow$ returns `168.0`.
5. **Step 5 (`AIMessage`):** The graph loops back to Gemini. Gemini reads the results, synthesizes the final combined answer, and exits to `END`.

## 4. Key Interview Questions

**Q: What is the purpose of a Conditional Edge in LangGraph?**
> **A:** Normal edges are deterministic (A always leads to B). A Conditional Edge acts like a routing function that dynamically chooses which node to go to next based on the current State.

**Q: Why does `ToolNode` route back to the LLM instead of going straight to the user?**
> **A:** Raw tool outputs are structured data (numbers, JSON, API strings). Routing back to the LLM allows the model to interpret the tool results, verify the user's intent was satisfied, and compose a natural conversational reply (or call another tool if needed).
